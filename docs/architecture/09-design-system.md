# 09 — Design System — White-Label Studio

**Date:** 2026-04-24 | **Updated:** 2026-04-29

## Design Philosophy

YBR Platform is a **white-label** course platform. The design system has **no brand color of its own**. Each creator injects exactly two CSS custom properties into `<html>` and the entire platform adapts automatically.

This means:
- The base neutral layer is permanent and never changes (warm stone, off-white — Notion-like)
- All interactive accents (`primary`) derive from the creator's brand color at runtime
- No hardcoded terracotta, gold, or any non-neutral hue in components

**Context files (required reading before any frontend work):**
- `PRODUCT.md` — register, users, brand personality, design principles
- `DESIGN.md` — visual tokens, typography, components (generated by `/impeccable document`)

Load both before starting any implementation:
```bash
node .claude/skills/impeccable/scripts/load-context.mjs
```

## White-Label Theming Model

### Per-Creator Brand Injection

The server layout injects only two variables on `<html>`:

```html
<html style="--color-primary: #3b82f6; --color-on-primary: #ffffff;">
```

All derived tints auto-compute via `color-mix`:

```css
:root {
  --color-primary-hover:     color-mix(in oklch, var(--color-primary) 82%, oklch(0 0 0));
  --color-primary-muted:     color-mix(in oklch, var(--color-primary) 10%, oklch(1 0 0));
  --color-primary-container: color-mix(in oklch, var(--color-primary) 6%, oklch(1 0 0));
}
```

### Theming Contract for Creators

| Variable | What the creator sets | Example |
|---|---|---|
| `--color-primary` | Main brand color | `#3b82f6`, `#e63946`, `#7c3aed` |
| `--color-on-primary` | Text color on primary bg | `#ffffff` or `#000000` |

Everything else is derived or comes from the permanent neutral layer.

## Typography

All fonts are Inter — single typeface, no serif display font. This ensures neutrality across all creator brands.

| Scale | Size | Weight | Line-height | Use |
|---|---|---|---|---|
| `display-lg` | 48px | 400 | 1.1 | Hero headlines |
| `display-md` | 36px | 400 | 1.2 | Section titles |
| `title-lg` | 28px | 500 | 1.3 | Page headings |
| `body-lg` | 18px | 400 | 1.6 | Lead paragraphs |
| `body-md` | 16px | 400 | 1.6 | Standard body text |
| `label-md` | 14px | 500 | 1.2 | Labels, metadata |
| `button` | 16px | 600 | 1 | Button text |

Cap body line length at **65–75ch** for readability.

## Shadows

All shadows are neutral (no color tinting). They never reference the creator's brand color.

```css
--shadow-card:       0px 1px 3px rgba(0,0,0,.07), 0px 1px 2px rgba(0,0,0,.05);
--shadow-card-hover: 0px 4px 12px rgba(0,0,0,.08), 0px 2px 4px rgba(0,0,0,.05);
--shadow-modal:      0px 20px 60px rgba(0,0,0,.12), 0px 4px 16px rgba(0,0,0,.06);
```

## Interface Rules

- **Language:** All user-facing text in Portuguese (pt-BR) via `next-intl`
- **Buttons:** `rounded-full`, min-height 48px, primary = creator's `--color-primary`
- **Cards:** white background, `border border-outline-variant`, `shadow-card`
- **Inputs:** `rounded-lg`, `border-outline-variant`, focus ring = `ring-primary`
- **Progress bars:** thin, neutral track (`surface-container`), fill = `primary`
- **Video player:** rounded corners, minimalist controls that use `primary` for seek/play
- **Spacing:** 8px base unit, section-gap 80px, container max 1280px
- **Mobile-first:** 16px margins on mobile, 24px gutters

1. **Before any UI work:** run `node .claude/skills/impeccable/scripts/load-context.mjs`
2. **For new features:** run `/impeccable craft [feature]`

4. **For production polish:** run `/impeccable polish [target]`
5. **PRODUCT.md** — always up to date at workspace root
6. **DESIGN.md** — run `/impeccable document` to regenerate when tokens change

All agents that touch frontend must satisfy the IMPECCABLE_PREFLIGHT gate before editing files.
